# 2.5 运行时多态只是一种抽象方式

许多面向对象课程把继承安排在类之后，于是容易形成一种错觉：只要需求出现了多个相似类型，就应该先寻找一个共同基类。

C++ 提供运行时多态，但它只是多种抽象方式之一。选择之前应先问：类型集合会不会扩展、具体类型在编译时是否已知、对象是否真的存在「是一个」的关系。

## 优先考虑组合

继承表达的是「派生类是基类的一种」，组合表达的是「一个对象拥有或使用另一个对象」。大多数复用需求其实属于后者。

假设成绩报告需要选择输出格式。报告**使用一个格式化器**，并不是报告**是一种格式化器**：

```cpp
class Formatter {
public:
    void print(std::span<const Student> students) const;
};

class Report {
public:
    explicit Report(Formatter& formatter) : formatter_{formatter} {}

    void print(std::span<const Student> students) const {
        formatter_.print(students);
    }

private:
    Formatter& formatter_;
};
```

组合让两部分职责独立：`Report` 决定何时产生报告，`Formatter` 决定如何表现数据。以后替换格式时不必修改报告本身。

这里的引用成员表示 `Report` 不拥有格式化器，因此调用者必须保证格式化器活得更久。如果报告需要独占拥有它，可以改用 `std::unique_ptr<Formatter>`。

## 虚函数提供运行时分派

如果格式类型由配置文件或用户输入在运行时决定，而且将来允许增加新的格式，可以定义抽象接口：

```cpp
#include <span>

class Formatter {
public:
    virtual ~Formatter() = default;

    virtual void print(std::span<const Student> students) const = 0;
};
```

`= 0` 使 `print` 成为纯虚函数，`Formatter` 因而是抽象类，不能直接创建对象。派生类提供实现：

```cpp
class TextFormatter final : public Formatter {
public:
    void print(std::span<const Student> students) const override {
        for (const Student& student : students) {
            std::cout << student.id << ' ' << student.name << ' '
                      << student.score.value() << '\n';
        }
    }
};
```

`override` 要求编译器检查这个函数确实覆盖了基类虚函数，可以发现参数或 `const` 写错导致的意外重载。`final` 表示不再允许从 `TextFormatter` 继续派生。

调用者通过基类引用或指针使用对象时，具体函数在运行时选择：

```cpp
void print_with(const Formatter& formatter,
                std::span<const Student> students) {
    formatter.print(students);
}
```

这就是运行时多态。它需要一次间接分派，并要求对象通过引用或指针使用；这些成本通常很小，但不应在没有需求时主动引入。

## 多态基类通常需要虚析构函数

如果通过基类指针销毁派生对象，基类析构函数必须是虚函数：

```cpp
std::unique_ptr<Formatter> formatter =
    std::make_unique<TextFormatter>();
```

`unique_ptr<Formatter>` 最终执行 `delete` 时，只知道静态类型是 `Formatter`。虚析构函数保证先运行派生类析构，再运行基类析构。

对没有虚析构函数的基类执行这种删除会产生未定义行为。只要一个类准备作为运行时多态接口使用，通常就在接口中写：

```cpp
virtual ~Formatter() = default;
```

这不表示所有基类都必须有虚析构函数。某些类并不允许通过基类指针删除，甚至根本不用于运行时多态。

## 当心对象切片

把派生对象按值转换成基类对象，只会保留基类子对象：

```cpp
#include <string>

struct Animal {
    std::string name;
    virtual std::string sound() const {
        return "?";
    }
};

struct Cat : Animal {
    std::string sound() const override {
        return "meow";
    }
};

Cat cat;
Animal animal = cat; // Cat 部分被切掉
std::cout << animal.sound(); // 输出 ?
```

这称为对象切片。多态对象通常通过引用或智能指针传递和存储：

```cpp
void speak(const Animal& animal) {
    std::cout << animal.sound();
}
```

`std::vector<Animal>` 也不能保存派生对象的完整状态。需要异构运行时多态集合时，常见写法是 `std::vector<std::unique_ptr<Animal>>`。

## 封闭类型集合可以使用 `variant`

如果所有可能类型在编译时已经确定，而且它们更像几种并列情况，可以使用 `std::variant`：

```cpp
#include <iostream>
#include <string>
#include <variant>

struct TextReport {
    std::string text;
};

struct CsvReport {
    std::string text;
};

using ReportData = std::variant<TextReport, CsvReport>;

void print(const ReportData& report) {
    std::visit(
        [](const auto& value) {
            std::cout << value.text << '\n';
        },
        report);
}
```

`variant` 保存的类型集合是封闭的：新增类型需要修改类型列表，并检查处理它的访问者。好处是对象保持值语义，不必建立共同基类，也不需要为每个对象单独动态分配。

当「新增操作」很多而「新增类型」很少时，`variant` 往往容易维护；当第三方需要不断增加新类型，而已有调用代码不应修改时，虚接口通常更合适。

## 编译期已知类型可以使用模板

如果具体类型在编译期已知，只要求它支持某些操作，可以使用模板：

```cpp
template <typename Formatter>
void print_with(const Formatter& formatter,
                std::span<const Student> students) {
    formatter.print(students);
}
```

这种方式不要求继承共同基类，编译器会为实际类型生成调用。C++20 concept 还能把「必须支持什么」写进模板约束。模板的错误信息、代码生成量和接口暴露方式也有自己的代价，将在第四篇详细讨论。

## 怎样选择抽象方式

| 情况 | 可以先考虑 |
| --- | --- |
| 只是复用实现或把职责拆开 | 组合、普通成员和普通函数 |
| 运行时选择类型，类型集合开放 | 虚函数和抽象接口 |
| 类型集合封闭，需要值语义 | `std::variant` |
| 具体类型编译期已知 | 模板和 concept |
| 分支很少、变化不频繁 | `enum class` 加普通分支也可能足够 |

继承树还应满足真正的替换关系：任何需要基类的地方都能合理使用派生类。仅仅字段相似、代码可以复用，并不足以证明这种关系。

## 再看成绩程序

学完前两篇后，我们可以再次重写项目首页中的程序。下面这版有意不使用继承：问题中没有需要运行时替换的学生类型，强行设计 `Person → Student` 只会增加概念。

```cpp
#include <cstddef>
#include <iostream>
#include <optional>
#include <ranges>
#include <string>
#include <utility>
#include <vector>

class Score {
public:
    [[nodiscard]] static std::optional<Score> from(int value) {
        if (value < 0 || value > 100) {
            return std::nullopt;
        }
        return Score{value};
    }

    [[nodiscard]] int value() const noexcept {
        return value_;
    }

    [[nodiscard]] bool passed(int threshold = 60) const noexcept {
        return value_ >= threshold;
    }

private:
    explicit Score(int value) : value_{value} {}

    int value_;
};

struct Student {
    int id{};
    std::string name;
    Score score;
};

std::optional<Student> read_student(std::istream& input) {
    int id{};
    std::string name;
    int raw_score{};

    if (!(input >> id >> name >> raw_score)) {
        return std::nullopt;
    }

    const auto score = Score::from(raw_score);
    if (!score) {
        return std::nullopt;
    }

    return Student{id, std::move(name), *score};
}

int main() {
    int count{};
    std::cout << "Number of students: ";
    if (!(std::cin >> count) || count < 0) {
        std::cerr << "Invalid student count\n";
        return 1;
    }

    std::vector<Student> students;
    students.reserve(static_cast<std::size_t>(count));

    std::cout << "Enter id, name and score for each student:\n";
    for (int index{}; index < count; ++index) {
        auto student = read_student(std::cin);
        if (!student) {
            std::cerr << "Invalid student data\n";
            return 1;
        }
        students.push_back(std::move(*student));
    }

    auto failed_students =
        students | std::views::filter([](const Student& student) {
            return !student.score.passed();
        });

    std::cout << "Students who failed:\n";
    for (const Student& student : failed_students) {
        std::cout << student.id << ' ' << student.name << ' '
                  << student.score.value() << '\n';
    }
}
```

这版程序体现了第二篇的几个选择：

- `Score` 是类，因为它必须维护 0 到 100 的不变量；
- `Student` 仍是聚合，因为三个成员可以分别理解；
- `read_student` 返回结果，不通过输出指针修改调用者对象；
- `optional` 明确表示读取可能失败；
- `vector`、`string` 和 `optional` 管理自身资源，程序遵循 Rule of Zero；
- `std::move` 把不再使用的局部值交给容器；
- 没有为了展示语法而引入继承和动态分配。

它仍然把「输入格式错误」和「分数越界」合并成了同一种失败，也没有拆分源文件、测试业务规则。第三篇将从这些问题继续，让它从一段现代 C++ 代码生长成一个小项目。

## 小结

- 组合通常比继承更直接地表达职责关系
- 虚函数适合运行时选择且类型集合开放的问题
- 多态基类通常需要虚析构函数
- 按值传递派生对象会发生对象切片
- `std::variant` 适合编译时已知的封闭类型集合
- 模板适合具体类型在编译期已知的抽象
- 不要为了展示面向对象而制造继承树
