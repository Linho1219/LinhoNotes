# 2.5 运行时多态只是一种抽象方式

到目前为止，我们定义的类都可以独立使用。本节才开始认识经典面向对象中的另一组概念：继承和多态。

我们会从语法和一个具体问题开始。等看清它究竟解决了什么，再讨论什么时候不应该使用它。

## 从两种通知方式开始

假设程序可以通过邮件或短信发送通知：

```cpp
#include <iostream>
#include <string_view>

class EmailNotifier {
public:
    void send(std::string_view message) const {
        std::cout << "Email: " << message << '\n';
    }
};

class SmsNotifier {
public:
    void send(std::string_view message) const {
        std::cout << "SMS: " << message << '\n';
    }
};
```

两个类都有 `send`，但它们是两个毫无关系的类型。如果要把「发送通知」写成一个函数，参数应该是什么类型？

```cpp
void alert(const EmailNotifier& notifier) {
    notifier.send("Server is down");
}
```

这个函数只能接受邮件通知器。可以再为 `SmsNotifier` 写一个重载，但每增加一种通知方式就要复制一次逻辑。

```cpp
void alert(const EmailNotifier& notifier) {
    notifier.send("Server is down");
}
void alert(const SmsNotifier& notifier) {
    notifier.send("Server is down");
}
```

这很不好。我们想要表达的是：对 `alert` 来说，这些对象都是「一种通知器」，都能执行
「发送消息」这项操作。

## 继承先建立类型关系

可以先定义一个更一般的 `Notifier`：

```cpp
class Notifier {
  public:
    void send(std::string_view message) const {
        std::cout << "Notification: " << message << '\n';
    }
};

class EmailNotifier : public Notifier {
};
```

`Notifier` 称为**基类**（base class），`EmailNotifier` 称为**派生类**（derived class）。`public Notifier` 表示公有继承，表达「`EmailNotifier` 是一种 `Notifier`」。

派生类会包含一个基类部分，因此它可以使用基类的公有成员：

```cpp
EmailNotifier email;
email.send("Hello"); // 调用 Notifier::send
```

更重要的是，需要 `Notifier` 引用的地方可以接受 `EmailNotifier` 对象：

```cpp
void alert(const Notifier& notifier) {
    notifier.send("Server is down");
}

EmailNotifier email;
alert(email);
```

这里没有复制对象。`notifier` 只是以基类的视角借用 `email`。

### 只有继承还不够

现在让邮件通知器实现自己的 `send`：

```cpp
class EmailNotifier : public Notifier {
public:
    void send(std::string_view message) const {
        std::cout << "Email: " << message << '\n';
    }
};

EmailNotifier email;
email.send("Hello"); // Email: Hello
alert(email);        // Notification: Server is down
```

结果可能出乎意料。直接用 `email` 调用时，编译器看到它的类型是
`EmailNotifier`，所以选择 `EmailNotifier::send`。在 `alert` 内，参数的类型却是
`const Notifier&`，所以选择了 `Notifier::send`。

仅有继承只建立了类型关系，不会自动带来运行时多态。

## 虚函数让运行时选择实现

把基类中的函数声明为 `virtual`：

```cpp
class Notifier {
public:
    virtual void send(std::string_view message) const {
        std::cout << "Notification: " << message << '\n';
    }
};

class EmailNotifier : public Notifier {
public:
    void send(std::string_view message) const override {
        std::cout << "Email: " << message << '\n';
    }
};
```

基类函数前的 `virtual` 表示：通过基类引用或指针调用这个函数时，要根据对象
的实际类型选择实现。派生类函数后的 `override` 要求编译器检查它确实在
重写某个虚函数。

```cpp
EmailNotifier email;
alert(email); // Email: Server is down
```

`alert` 编译时只知道自己拿到了 `Notifier`，程序运行到 `notifier.send(...)`
时才根据实际对象选择 `EmailNotifier::send`。这就是**运行时多态**：
同一个调用接口，面对不同的实际对象会有不同行为。

> [!important]
>
> 只有通过基类的**引用或指针**调用虚函数时，才会发生这种动态选择。

### `override` 是一项编译期检查

派生类函数的参数、`const` 等必须与基类匹配。例如遗漏 `const`：

```cpp
class SmsNotifier : public Notifier {
public:
    void send(std::string_view message) override { // [!code error]
        std::cout << "SMS: " << message << '\n';
    }
};
```

如果没有 `override`，这可能只会意外定义出另一个函数。写上 `override` 后，编译器会
指出它没有成功重写基类函数。因此，重写虚函数时应当始终写 `override`。

## 抽象类只规定接口

「普通通知」并没有明确的发送方式。`Notifier` 不需要提供一个默认实现，
只要求每种具体通知器实现 `send` 即可。可以把它写成**纯虚函数**：

```cpp
class Notifier {
public:
    virtual ~Notifier() = default;
    virtual void send(std::string_view message) const = 0;
};
```

`= 0` 不是把函数赋值为数字零，而是 C++ 表示纯虚函数的特殊语法。析构函数前的
`virtual` 稍后解释。包含纯虚函数
的类是**抽象类**，不能直接创建它的对象：

```cpp
Notifier notifier; // [!code error]
```

它的作用是规定共同接口。派生类如果想成为可创建对象的具体类，就必须实现
这些纯虚函数。

```cpp
class EmailNotifier final : public Notifier {
public:
    void send(std::string_view message) const override {
        std::cout << "Email: " << message << '\n';
    }
};

class SmsNotifier final : public Notifier {
public:
    void send(std::string_view message) const override {
        std::cout << "SMS: " << message << '\n';
    }
};
```

`final` 表示不允许再从这个类派生新类。它并非必需，只是把这两个类是最终的具体
实现这一设计意图写了出来。

## 运行时选择具体类型

如果用户可以在运行时选择通知方式，程序要先创建对应的具体对象，然后通过
统一的 `Notifier` 接口使用它。

```cpp
#include <memory>
#include <string>

std::unique_ptr<Notifier> make_notifier(std::string_view kind) {
    if (kind == "email") {
        return std::make_unique<EmailNotifier>();
    }
    if (kind == "sms") {
        return std::make_unique<SmsNotifier>();
    }
    return nullptr;
}
```

`std::unique_ptr<Notifier>` 表示这个指针独占拥有「某种 `Notifier`」，具体是哪一种可以
在运行时决定。

```cpp
const auto notifier = make_notifier("sms");
if (notifier) {
    notifier->send("Server is down"); // SMS: Server is down
}
```

这段代码把前几节的概念连了起来：

- `unique_ptr` 表达对动态对象的独占所有权；
- 基类指针可以指向派生对象；
- 通过基类指针调用虚函数时，程序选择实际类型的实现。

### 为什么需要虚析构函数

上面的指针声明为 `unique_ptr<Notifier>`，但它可能实际拥有 `EmailNotifier`。
指针销毁对象时，必须先析构完整的派生类对象，再析构它的基类部分。

因此，准备被这样多态使用的基类需要虚析构函数：

```cpp
class Notifier {
public:
    virtual ~Notifier() = default;
    virtual void send(std::string_view message) const = 0;
};
```

`= default` 要求编译器生成普通的析构实现；`virtual` 保证通过基类指针销毁对象时，
完整的派生对象会被正确析构。否则，这种销毁会导致未定义行为。

> [!note]
>
> 这不意味着每个类都应该有虚析构函数。这是为「通过基类指针销毁派生对象」
> 服务的。不作为多态基类使用的类通常不需要它。

## 对象切片会丢掉派生部分

为什么前面始终使用基类引用或指针，而不直接按值传递？看看下面的代码：

```cpp
void alert(Notifier notifier); // 按值接收

EmailNotifier email;
alert(email);
```

但现在 `Notifier` 是抽象类，根本不能按值创建，这段代码无法编译。即使基类不是
抽象类，按值复制时也只会复制其中的基类部分，派生类增加的状态会被丢掉。
这称为**对象切片**（object slicing）。

因此，运行时多态对象通常：

- 使用 `Base&` 或 `const Base&` 借用；
- 使用 `Base*` 表达可空借用；
- 使用 `std::unique_ptr<Base>` 表达所有权；
- 在容器中保存 `std::unique_ptr<Base>`，而不是把派生对象塞进
  `std::vector<Base>`。

## 继承必须表达「是一种」

看懂继承的机制不等于应该到处使用继承。公有继承做出了一个很强的承诺：
派生类是基类的一种，任何需要基类的地方都应当能合理使用派生类。

`EmailNotifier` 作为一种 `Notifier` 说得通。但如果报告需要使用一个格式化器，
「报告是一种格式化器」就说不通。这种需求应当使用**组合**：

```cpp
class Formatter {
public:
    std::string format(std::string_view text) const;
};

class Report {
public:
    explicit Report(Formatter formatter)
        : formatter_{std::move(formatter)} {}

private:
    Formatter formatter_;
};
```

`Report` **拥有一个** `Formatter`，而不是**是一种** `Formatter`。组合还可以通过
重用现成类型实现功能，却不会建立不真实的类型关系。所以「组合优于继承」不是
说继承永远错误，而是提醒我们先区分「有一个」与「是一种」。

## 不同问题有不同的抽象方式

运行时多态适合这样的问题：

- 具体类型需要在运行时选择；
- 不同类型要通过一组稳定的共同操作使用；
- 以后可能添加新的具体类型，而调用者不应随之修改。

它不是唯一选择：

| 情况 | 可以先考虑 |
| --- | --- |
| 只是拆分职责或重用功能 | 组合、普通成员和普通函数 |
| 运行时选择类型，将来还可增加新类型 | 虚函数和抽象接口 |
| 所有可能类型已在编译时确定 | `std::variant` |
| 具体类型在编译时已知 | 模板和 concept |
| 情况很少且变化不频繁 | `enum class` 加普通分支 |

### 封闭的类型集合可以用 `variant`

如果程序只会有邮件和短信两种通知，类型列表是封闭的，可以不建立继承树。
在这种设计中，`EmailNotifier` 和 `SmsNotifier` 可以是本节开头那样的两个独立类：

```cpp
#include <variant>

using AnyNotifier = std::variant<EmailNotifier, SmsNotifier>;

void alert(const AnyNotifier& notifier) {
    std::visit(
        [](const auto& concrete_notifier) {
            concrete_notifier.send("Server is down");
        },
        notifier);
}
```

`variant` 像一个「当前保存列表中某一种类型」的安全联合。新增通知类型时需要修改
这个列表，但对象仍可以直接按值保存，也不需要单独动态分配。

### 编译期已知类型可以用模板

如果调用某个函数时已经知道具体类型，只希望它有 `send` 操作，模板就足够：

```cpp
template <typename T>
void alert(const T& notifier) {
    notifier.send("Server is down");
}
```

这个版本不要求 `T` 继承 `Notifier`。编译器会为实际类型生成调用；C++20
concept 还可以明确表达「要求它能做什么」。模板将在第四篇详细讨论。

## 再看成绩程序

学完前两篇后，我们可以再次重写项目首页中的程序。下面这版有意不使用继承：
问题中没有需要在运行时替换的学生类型，强行设计 `Person → Student` 只会增加概念。

```cpp
#include <cstddef>
#include <iostream>
#include <optional>
#include <ranges>
#include <string>
#include <utility>
#include <vector>

class Score {
public:
    [[nodiscard]] static std::optional<Score> from(int value) {
        if (value < 0 || value > 100) {
            return std::nullopt;
        }
        return Score{value};
    }

    [[nodiscard]] int value() const noexcept {
        return value_;
    }

    [[nodiscard]] bool passed(int threshold = 60) const noexcept {
        return value_ >= threshold;
    }

private:
    explicit Score(int value) : value_{value} {}

    int value_;
};

struct Student {
    int id{};
    std::string name;
    Score score;
};

std::optional<Student> read_student(std::istream& input) {
    int id{};
    std::string name;
    int raw_score{};

    if (!(input >> id >> name >> raw_score)) {
        return std::nullopt;
    }

    const auto score = Score::from(raw_score);
    if (!score) {
        return std::nullopt;
    }

    return Student{id, std::move(name), *score};
}

int main() {
    int count{};
    std::cout << "Number of students: ";
    if (!(std::cin >> count) || count < 0) {
        std::cerr << "Invalid student count\n";
        return 1;
    }

    std::vector<Student> students;
    students.reserve(static_cast<std::size_t>(count));

    std::cout << "Enter id, name and score for each student:\n";
    for (int index{}; index < count; ++index) {
        auto student = read_student(std::cin);
        if (!student) {
            std::cerr << "Invalid student data\n";
            return 1;
        }
        students.push_back(std::move(*student));
    }

    auto failed_students =
        students | std::views::filter([](const Student& student) {
            return !student.score.passed();
        });

    std::cout << "Students who failed:\n";
    for (const Student& student : failed_students) {
        std::cout << student.id << ' ' << student.name << ' '
                  << student.score.value() << '\n';
    }
}
```

这版程序体现了第二篇的几个选择：

- `Score` 是类，因为它必须维护 0 到 100 的不变式；
- `Student` 仍是聚合，因为三个成员可以分别理解；
- `read_student` 返回结果，不通过输出指针修改调用者对象；
- `optional` 明确表示读取可能失败；
- `vector`、`string` 和 `optional` 管理自身资源，程序遵循 Rule of Zero；
- 没有为了展示语法而引入继承和动态分配。

它仍然把「输入格式错误」和「分数越界」合并成了同一种失败，也没有拆分源文件、
测试业务规则。第三篇将从这些问题继续，让它从一段现代 C++ 代码生长成一个小项目。

## 小结

- 公有继承表达「派生类是基类的一种」
- 虚函数使基类引用或指针能在运行时选择具体实现
- 纯虚函数只规定操作，使类成为不能直接实例化的抽象类
- 重写虚函数时应当写 `override`
- 通过基类指针销毁派生对象时，基类需要虚析构函数
- 多态对象通常通过引用或指针使用，按值复制可能产生对象切片
- 组合表达「有一个」，继承表达「是一种」
- 运行时多态只是一种抽象方式，有时 `variant`、模板或普通分支更合适
