## 第一个 C++ 程序

欢迎来到 C++ 的世界！这是一门十分强大，但学习曲线较为陡峭的语言。我们来编写我们的第一个 C++ 程序，这个程序输出一行 `Hello world!` 并返回 `0`：

```cpp
#include <iostream> // 预编译指令

using namespace std; // 声明使用 std 命名空间

int main() { // main 函数是一切 C++ 程序的起始点
    cout << "Hello world!" << endl;
    return 0; // 在 C++ 新标准中可以不写这行
}
```

下面我们来详细讲解一下这个程序中出现的各种语句的含义。

1. `#include <iostream>`  
   预编译指令，这行代码告诉编译器：我们需要在这个程序中包含 `iostream` 头文件。
2. `using namespace std;`  
   `using` 指令，告诉编译器默认包含 `std` 命名空间的所有函数与变量，不需要使用std::前缀指定；
3. `int main()`  
   `main` 函数是所有 C++ 程序的起点，所有 C++ 程序必须包含 `main` 函数才能成功编译并运行。函数后面的大括号中括起来的部分称为函数体，描述了函数的行为。在这个例子中，`main` 函数的行为是：输出 `Hello world!` 并返回 `0`。
4. `cout` 语句  
   执行了输出 `"Hello world!"` 这一操作并换行。`<<` 运算符在 `cout` 中表示将其后面的内容「推入」到前面的对象中。
5. `return 0`  
   描述了函数的返回结果。在这个例子中，`main` 函数返回 `0`，也是整个程序的返回结果。C++ 中的 `main` 函数返回值与程序返回值相同，返回 `0` 表示程序运行成功，返回非 `0` 表示失败。非零返回值也可以用来表示错误原因，例如在一些系统中，`0xC0000005` 返回值表示程序访问到了内存中不属于该程序的位置。在较新的 C++ 标准中，如果 `main` 函数没有指定返回值，编译器会默认让程序返回 `0`。

如果程序中不包含 `main` 函数，会发生什么呢？我们将上面程序中的 `main` 函数部分去除，再次编译，编译器输出如下：

```

[100%] Linking CXX executable expLinux
/usr/bin/ld: /usr/lib/gcc/aarch64-linux-gnu/12/../../../aarch64-linux-gnu/Scrt1.o: in function `_start':
(.text+0x1c): undefined reference to `main'
/usr/bin/ld: (.text+0x20): undefined reference to `main' # 这里提示了找不到main函数
collect2: error: ld returned 1 exit status
make[2]: *** [CMakeFiles/expLinux.dir/build.make:97: expLinux] Error 1

```

可以发现，编译器提示了我们没有main函数，因此拒绝继续编译程序。

## 注释

C++ 使用 `//` 来做单行注释，使用 `/* 注释内容 */` 来写多行注释。多行注释的使用方法如下：

```cpp
/**
 * @brief 记录信息级别日志
 * @param message 要记录的日志消息
 */
void Logger::Info(const QString& message) {
    qInfo().noquote() << QDateTime::currentDateTime().toString("yyyy-MM-dd hh:mm:ss:zzz") << "[INFO]" << message;
}
```

在上面，我们将内容通过 `/* ... */` 包含，实现了 C++ 的多行注释。

## `include` 指令与头文件命名

在最开始时，我们使用 `#include` 包含的文件在 C++ 中称为**头文件**。头文件是 C++ 中十分重要的文件，用于描述各类基础库与用户自定义库的实现方式。C++ 中头文件的命名方式约定如下：

| 类型                            | 命名约定                                                     |
| ------------------------------- | ------------------------------------------------------------ |
| C 头文件或 C++ 中比较旧的头文件 | 用 `.h` 结尾，例如 `stdio.h`                                 |
| C++ 中较新的头文件              | 没有扩展名，例如 `iostream`                                  |
| C 中迁移到 C++ 的头文件         | 以 `c` + 旧头文件名命名，没有扩展名，例如 `math.h` → `cmath` |

## `using` 指令

> [!TIP]
>
> **名词解释：命名空间**
>
> 命名空间，namespace，可以理解为一个「小组」，其中可以放置类、函数、变量等，不同命名空间内可以定义同名内容，便于组织代码并避免重名。例如：
>
> ```cpp
> #include <iostream>
>
> namespace First {
> void show() { std::cout << "First namespace" << endl; }
> } // namespace First
>
> namespace Second {
> void show() { std::cout << "Second namespace" << endl; }
> } // namespace Second
>
> int main() {
>     First::show();  // 输出 First namespace
>     Second::show(); // 输出 Second namespace
> }
> ```

`using` 指令用于告诉编译器包含整个命名空间内的内容，或包含命名空间内的特定成员。例如：

```cpp
using namespace std; // 使用整个 std 命名空间

using std::cout; // 仅使用 std 中的 cout
```

在实际的项目开发中，更推荐后者的写法，因为后者能够保证命名空间不被污染。

> [!TIP]
>
> **名词解释：命名空间污染**
>
> 指在某个头文件中使用了整个命名空间，导致包含这个文件的所有源文件被迫使用了相同命名空间的现象。例如：在 C++ OpenCV 中，OpenCV 对应的命名空间是 `cv2`，但如果在某个头文件中使用了整个 `cv2` 命名空间，而源文件中又使用了自定义的同名命名空间，如果这两个命名空间中包含了相同的函数或变量名，同时包含这两个命名空间就会导致歧义。

## 变量

与其他编程语言相同，C++ 对变量也提供了丰富的支持。使用如下格式来声明变量：

```
[数据类型] [变量名];
```

数据类型描述了这个变量存储的值类型，而变量名描述了访问这个变量的方式。例如我们用下面的代码声明一个变量：

```cpp
int value;
```

其中 `int` 描述了这个变量存储的值 —— 整数；而 `value` 描述了访问变量的方式——通过名称 `value` 进行访问。

需要注意的是，C++ 的变量**没有固定的初始值**，变量的初始值由使用变量时内存的内容决定（全局变量除外，将在 [后续](./6-多文件编译、变量高级与类基础) 说明），所以一般需要给变量赋初始值。

以上述的 `value` 为例，C++ 使用 `=` 为变量赋值：

```cpp
value = 0;
```

当然我们也可以将变量声明与赋值组合，通过如下语句同时声明变量与赋初始值：

```cpp
int value = 0;
```

在 C++ 中，变量需要声明才能访问。如果没有声明变量直接使用，编译器会指出变量未声明。例如我们需要编译下面的程序：

```cpp
#include <iostream>

using std::cout;
using std::endl;

int main() {
    cout << val << endl; // [!code error]
    return 0;
}
```

编译输出如下：

```

/home/orangepi/CLionProjects/expLinux/main.cpp: In function ‘int main()’:
/home/orangepi/CLionProjects/expLinux/main.cpp:7:17: error: ‘val’ was not declared in this scope
    7 |         cout << val << endl;
      |                 ^~~
make[2]: *** [CMakeFiles/expLinux.dir/build.make:76: CMakeFiles/expLinux.dir/main.cpp.o] Error 1
make[1]: *** [CMakeFiles/Makefile2:83: CMakeFiles/expLinux.dir/all] Error 2
make: *** [Makefile:91: all] Error 2
```

C++ 的这种特性是其**静态类型**性质的表现。与 Python 不同，Python 不需要预先声明变量，而是直接为变量赋值，Python 解释器会自动创建变量。

> 例如：
>
> ```py
> resp = requests.get(filelist_url, headers=headers)
> resp.raise_for_status()
> filelist_soup = BeautifulSoup(resp.content, "html.parser")
> res_list = [source.get('src') for source in filelist_soup.find_all('source', type="audio/mpeg")]
> i = 0
> if not res_list:
>     with open("error.html", "w") as f:
>         f.write(resp.text)
>     logger.error("未找到任何可爬取音频")
>     exit(1)
> ```
>
> 在这里，我们并没有声明 `resp`、`res_list` 与 `i` 等变量，而是直接赋值。Python 解释器会自动创建这些变量并赋值，当我们访问这些变量时，这些变量的值就是我们为这些变量赋的值。

乍一看，静态变量的写法更复杂、需要先声明后访问，不如 Python 的就地创建易用。但是，先声明后使用的模式可以让编译器及早地发现代码中的错误。例如，如果我们意外写错了变量名称，C++ 编译器在编译时就能发现错误，而 Python 需要在程序实际运行到该处时才会报错。当项目规模增大时，静态检查能帮助我们省下很多时间精力。

## 输入输出

在 C++ 中，输入输出主要依靠 `cin` 与 `cout` 实现。例如，输出语句的编写方式如下：

```cpp
cout << "Hello\n"; // 这里 \n 的作用与 endl 相同
cout << "World!\n";
```

上面语句的输出如下：

```
Hello
World!
```

双引号中以 `\` 开头的部分称为转义字符，转义字符能够实现丰富的文本输出功能。这里使用 `\n` 的好处是我们不需要额外声明使用 `endl`，非常适合这样以字符串为结尾的内容。

在 C++ 中，使用 `cin` 的方式如下：

```cpp
cin >> [要赋值的变量];
```

下面的程序会要求用户输入名字，并输出问候：

```cpp
#include <iostream>
#include <string> // string 头文件为 C++ 提供了易用的字符串支持

using std::cout;
using std::cin;
using std::string; // C++ 的字符串类型
using std::endl;

int main() {
    string name;
    cout << "Enter your name: ";
    cin >> name;
    cout << "Hello, " << name << "!\n";
    return 0;
}
```

上面程序会输出：

```
Enter your name:
```

并等待用户输入。在输入名字 `Peter` 并按下 <kbd>Enter</kbd> 键后，会继续输出 `Hello, Peter!`。

```
Enter your name: Peter
Hello, Peter!
```

## 函数

在最开始的例子中，我们说明了 `main` 函数的作用，也知道了 `main` 函数是 C++ 程序的起点。在 C++ 中，我们可以声明与定义任意函数，格式如下：

```
[返回类型] [函数名]([参数列表]) {
    [函数体]
}
```

其中：

- 返回类型：我们期望函数调用后返回的数据类型；
- 函数名：我们调用这个函数的方式；
- 参数列表：我们期望交由函数处理的数据列表。

例如，我们需要定义一个 `add` 函数，这个函数接收两个整数，返回这两个整数相加的结果，代码如下：

```cpp
int add(int a, int b) {
    return a + b;
}

int x = 1;
int y = 2;
int z = add(x, y); // z 的值是 x 和 y 相加结果，这里为 3
```

理论上，C++ 的函数参数列表可以由无限个参数组成，并且返回值也可以是任意类型。如果某个函数的返回类型为 `void`，说明这个函数没有返回值。例如：

```cpp
void output(int result) {
    cout << "The result is " << result << "!\n";
}

output(42); // 输出 The result is 42!
```

C++ 的函数允许先声明后定义。例如，对于上述的 add 函数，有两种声明方式：

```cpp
// 方式一
int add(int m, int n);

// 方式二
int add(int, int);
```

其中方式二的声明方式更简洁，方式一则更注重参数的名称。

这样我们可以先声明函数，然后再定义函数体。例如：

```cpp
int add(int m, int n);

int main() {
    int x = add(1, 2);
    cout << "1 + 2 = " << x << endl;
    return 0;
}

int add(int a, int b) {
    return a + b;
}
```

值得一提的是，使用方式一时，声明中的参数名称无需与定义中的参数名称相同，只需保证类型一一对应即可。

这样做是因为 C++ 中函数必须先声明再使用，而在组织代码时我们并不总是想把函数体写在所有调用之前。对于调用方而言，函数是一个黑盒，无法看到内部构造，重要的只有函数的名称及其参数和返回值类型。因此只要提前声明函数的这些性质，就可以直接开始使用而无需提前写好函数体。函数体可以在后续代码中定义。

我们会在 [后续章节](./5-函数) 里更详细地介绍函数。

## 程序的编译与运行

### 直接使用编译器

在前面的内容中，我们大量提到了编译与运行结果。C++ 程序是怎样运行的？编译是什么？在下面的内容中，我们会逐一解答这些问题。

C++ 是一种**编译型语言**，也就是说，C++ 代码需要一个称作**编译器**的程序来将 C++ 程序转换为可执行文件。与编译型语言相对的是解释型语言。

> [!TIP]
>
> **名词解释**
>
> **编译型语言**：指需要编译器将程序代码翻译为机器码后才能够执行程序的语言。例如 C++、Rust、Go 等。
>
> **解释型语言**：指不需要编译，由解释器将程序代码实时翻译为机器码执行的语言。例如 Python、JavaScript、R 语言等。

在 Linux 下，我们常用 GCC 编译器。GCC 全称 **G**NU **C** **C**ompiler，是编译 C/C++ 语言的工具。在 Linux 下，我们通过如下命令安装它：

```sh
sudo apt install g++ # Ubuntu
sudo yum install gcc-c++ # RHEL/CentOS等
sudo zypper in gcc-c++ # OpenSUSE
sudo pacman -S g++ # Arch Linux
```

在安装 C++ 编译器后，假设要编译的文件名为 `main.cpp`，我们可以通过如下命令编译它：

```sh
g++ main.cpp
```

这行命令会在当前目录下生成一个 `a.out` 文件，这个 `a.out` 文件就是我们编写的程序的编译结果。

如果编译新的程序，那么原来的 `a.out` 就会被覆盖为新程序的代码。还可以通过 `-o` 参数指定输出文件位置。例如：

```sh
g++ -o my_program main.cpp
```

这样生成的可执行文件名为 `my_program`。我们可以利用命令行来验证这一点：

```sh
$ file my_program
my_program: ELF 64-bit LSB pie executable, ARM aarch64, version 1 (SYSV), dynamically linked, interpreter /lib/ld-linux-aarch64.so.1, BuildID[sha1]=470aad7a798ab4b0025e09e585bdbafae8930655, for GNU/Linux 3.7.0, not stripped
```

结果显示 `my_program` 为针对 ARM64 平台编译的 ELF 可执行文件。根据编译时使用的计算机的 CPU 架构不同，`file` 命令的结果也会发生变化。这里由于编译该程序的计算机为 ARM64 架构，所以结果为 `aarch64` 可执行文件。如果在常规的 64 位 x86 PC 上编译程序，结果为 `amd64`。

使用如下命令来执行我们刚刚编译好的程序：

```sh
./my_program # 具体文件名以自己设置的输出文件名为准
```

### 使用构建系统进行编译

上面的方式让我们能够以最基础的方式编译 C++ 程序，但是在一些规模庞大的项目（例如 Linux 内核、STM32 或 Arduino）中，仅依靠这种方式逐个文件编译程序是几乎不可能的，所以在一般的开发中，我们会使用一些现代化的构建系统（例如 Make 和 CMake 等）进行自动化编译与链接。

> [!TIP]
>
> **名词解释：链接**
>
> 在 C++ 程序中，我们能够指定在编译时输出链接文件，这样可以省去重复编译的时间。在修改某个或某些文件后，只需要重新编译这些更改的文件并且与其他文件重新组合成可执行文件即可。将链接文件组合成可执行文件的过程称为链接。

下面以 CMake 为例，说明如何通过 CMake 进行项目的系统化编译。

> [!TIP]
>
> **名词解释：CMake**
>
> CMake 是一个十分强大的跨平台编译工具链管理工具，支持将不同的源文件设置编译成不同的可执行文件、在编译前后执行自动化操作、链接第三方程序库、为不同操作系统、不同架构的 CPU 定制编译过程等功能。

在使用 CMake 编译项目时，我们需要创建一个 CMakeLists.txt 文件，这个文件向 CMake 详细描述了要使用的 C++ 标准、如何处理所有源文件、在编译前和编译后需要做什么等。对于上面的项目，我们可以这样编写 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.11) # 这里描述了CMake的最低版本，只有高于指定版本的CMake能够编译程序
project(my_program) # 这里描述了项目的名称

set(CMAKE_CXX_STANDARD 11) # 这里描述了我们要使用的C++标准是C++11

add_executable(my_program
        main.cpp) # 这里向CMake描述了如何处理源文件（这里是将main.cpp编译成my_program）
```

在编写好 `CMakeLists.txt` 后，我们便可以使用如下命令让 CMake 生成编译配置文件：

```sh
cmake -B build .
```

这里的 `build` 表示我们希望将编译配置文件存放在 `build` 文件夹，而最后的 `.` 则表示我们希望针对当前目录生成编译配置。CMake 会自动检测系统中是否存在对应的编译器、生成编译配置文件。输出如下：

```

-- Detecting C compiler ABI info - done
-- Check for working C compiler: /usr/bin/cc - skipped
-- Detecting C compile features
-- Detecting C compile features - done

-- Detecting CXX compiler ABI info - done
-- Check for working CXX compiler: /usr/bin/c++ - skipped

-- Detecting CXX compile features - done

```

接下来，我们转到编译配置目录并编译程序：

```sh

```

命令行输出如下：

```

[100%] Linking CXX executable my_program
[100%] Built target my_program
```

这时，我们就可以像之前一样执行我们的程序了。这样的流程对于只有一个源文件的程序来说稍显麻烦，但如果涉及到多个源文件以及有第三方库接入的项目来说，这样的管理工具就是十分有必要甚至不可或缺的。例如以下的 CMake 文件实现了一个基于 HAL 库的 STM32 单片机固件编译：

### 调试与分析

在开发过程中，如果程序的某一部分出了问题，怎么办呢？编译器会帮助我们拦截语法错误的代码进入编译过程，但如果代码的语法正确，但设计不符合预期呢？这个时候我们就需要使用一种叫做调试器的程序对程序进行调试，找出问题所在。具体调试方法见 [附录2](附录2-调试)。

### C++ 标准

C++ 的标准化工作始于 1990 年，最初由 ANSI 主导，后转为 ISO 与 ANSI 共同制定标准。最早制定的标准是 C++98（ISO/IEC 14882:1998），该标准全面规范了 C++ 语言特性，为不同编译器实现统一的程序行为提供了明确指导。ANSI/ISO C++ 还定义了标准类库，规定了所有合规 C++ 系统库应具备的基本功能集。

目前最新标准为 C++26，结尾的两位数字表示其发布年份，即 C++26 是 2026 年发布的。但实际项目中普遍采用 C++11 或 C++14 版本，少数技术前瞻性项目会选择 C++17 或 C++20 标准，而采用 C++23 及以上标准的项目则极为罕见。

~~简单一句话概括就是：如此生活三十年，直到大厦崩塌~~。事实上，近年来由于Rust等语言的出现，确实有人认为 C++ 的地位受到了一定挑战。

### 编译优化

可以通过命令行参数来对C++程序进行编译优化。例如：

```sh
g++ -O2 -o my_program main.cpp
```

C++ 编译优化有多个等级，例如 O0（默认行为）、O1、O2、O3 等。其中最常用的优化是 O2 优化，也被形象地称为“吸氧”。~~毕竟-O2也可以理解为减少氧气的量~~ ~~那-O3是不是吸臭氧~~

通过这些编译优化，编译器能够在不改变程序语义的前提下减小程序体积并提高运行效率。更准确地来说，O2 优化主要做了以下工作：

- **内联（Inline）** 小函数，减少函数调用开销
- **循环展开（Loop Unrolling）**，减少循环控制开销
- **死代码消除（Dead Code Elimination）**，移除永远不会执行的代码
- **常量折叠（Constant Folding）**，在编译期计算常量表达式
- **寄存器分配优化**，减少内存访问

以STM32中固件的编译为例，这里使用的例程是使用HAL库编写的联网温湿度计固件，编译结果如下：

```text
   text    data     bss     dec     hex    filename
  52552     132   16752   69436   10f3c    path/to/thermal_wireless_hal.elf
```

可以看到闪存中的代码已经占用了 52552 字节的空间。对于STM32F103C8T6，其闪存最大存储空间为 64K，也就是说我们的固件 `text` 段大小不能超过 65536，否则固件将无法烧录到单片机。这个占用对于 64K 的空间来说已经不充裕。我们可以计算一下剩余空间：

$$
\begin{gathered}
65536 - 52552 = 12984 \operatorname {Bytes} \\
12984 \div 1024 \approx 12.67 \operatorname {KBytes}
\end{gathered}
$$

整个闪存只剩下了 12.6K 空间，已经不太充裕。如果之后需要增添新功能，可能需要面临闪存空间不足的情况。这时我们为固件加上 O2 优化，编译结果如下：

```text
   text    data     bss     dec     hex    filename
  39300     128   16768   56196    db84    path/to/thermal_wireless_hal.elf
```

这次闪存中代码只使用了 39300 字节的空间，相比没有开启 O2 优化的情况节省了 25% 左右的空间。我们可以用以下方式来计算释放出来的空间：

$$
\begin{gathered}
52552 - 39300 = 13252 \operatorname {Bytes} \\
13252 \div 1024 \approx 12.94 \operatorname {KBytes}
\end{gathered}
$$
