# VitePress 实现短链接分享

## 基本逻辑

- 新版短链接的格式为 `https://notes.linho.cc/s?p=xxxxxxx`，其中 `p=` 后面是 7 位 Base62 字符（`0-9a-zA-Z`）
- 旧版短链接的格式为 `https://notes.linho.cc/s?q=xxxxxxxxxx`，为保持兼容仍然支持，其中 `q=` 后面 10 位十六进制字符（`0-9a-f`）
- Vite 在构建时为当前页面生成新旧两张 ID — 路径映射表，发现碰撞时直接终止构建
- 通过路由覆写，将 `/short-url.md` 映射到 `/s`，该 Markdown 文件内加载跳转组件
- 映射表通过虚拟模块只打包进 `/s` 页面的 JS chunk
- 在导航栏上注册分享组件，提供分享二维码和复制链接按钮

## 短 ID 的生成

旧版 ID 的生成逻辑是取页面路径的 MD5，将十六进制字符串（`0-9a-f`）的前 10 位作为 ID。编码空间为 $40\operatorname {bit}$。

但是只使用 `0-9a-f` 未免还是太浪费了。于是新版 ID 把完整 MD5 视为整数，对 $62^7$ 取模，再固定编码为 7 位 Base62（`0-9a-zA-Z`）。编码空间约为 $41.68\operatorname {bit}$，略大于旧版。

路径归一化、新旧 ID 计算和分享 URL 的生成都放在共享模块中，避免构建端与浏览器端出现不一致。

## 构建阶段：生成虚拟模块

Vite 插件从 VitePress 已解析的 `pages` 与 `rewrites` 获取实际路由，然后生成 `legacy` 和 `current` 两张映射表。

<<< @/.vitepress/node/vite/map-short-url.ts

在 `config.mts` 中将它注册为 Vite 插件：

```ts [.vitepress/config.mts]
vite: {
  plugins: [
    // ...
    mapShortUrl(),
  ],
},
```

使用虚拟模块的好处是，信息直接加入页面 chunk，不会引入额外的网络请求与缓存错配问题。（旧版用的是在构建时把 JSON 映射表放进 `public` 的方案）

## 客户端：查表与跳转

跳转组件使用 `URLSearchParams` 读取参数：

- 严格匹配 7 位 `[0-9A-Za-z]` 的 `p` 参数时查新表；
- 严格匹配 10 位 `[0-9a-f]` 的 `q` 参数时查兼容表；
- 参数无效或查不到路径时跳转到 404 页面。

## 客户端：分享组件

网页上生成短链接只需调用共享的 `createShareUrl`。该函数会比较完整直链与短链的实际长度，只在短链确实更短时使用 `/s?p=...`。

```ts
watchEffect(() => {
  link.value = createShareUrl(
    import.meta.env.DEV ? location.origin : site.baseUrl, // 方便开发环境测试
    page.value.filePath,
  )
})
```

至于二维码和复制按钮等展示细节，可以直接 [查看代码](https://github.com/Linho1219/LinhoNotes/blob/main/.vitepress/theme/features/short-url/share.vue)。

## 限制

在页面路径变化（移动、重命名）后短链接会失效。事实上页面路径变化后原始的链接也会失效，所以短链接一起失效也很合理。只不过原始链接因为是语义化的，至少还能知道原来大概是个什么东西，短链接就彻底看不出来了。

短链接在社交平台等场景下没有元数据，例如标题、简介等。因为绝大部分平台在抓取页面元数据时都是静态请求，不会运行页面上的 JS。如果要实现短链接元数据，需要服务器在响应短链接时查询对应页面并随附元数据，在本站这样的静态架构上是无法实现的。
